# Glass / TabBar performance harness

Run from the repository root:

```sh
bunx vite --config apps/docs/tests/performance/vite.config.ts
```

Open `http://127.0.0.1:3011` in the browser used for comparison. Keep the
tab in the foreground, use the same window size, display and reduced-motion
setting, and press **Run benchmark**. Save the JSON output for both revisions
and repeat runs to distinguish regression from measurement noise.

Compare saved reports with:

```sh
bun apps/docs/tests/performance/compare.ts baseline.json optimized.json
```

The harness renders the real shared components with one and eight glass
surfaces plus a TabBar, then measures:

- SVG filter preparation: displacement map and DOM definition updates. The
  browser's backdrop raster and paint are not part of this timing.
- Frame intervals from `requestAnimationFrame` while idle, during a TabBar
  long press with 60 generated moves, and after a strength-only update.
- React Profiler commits and supported browser long tasks.

Pointer moves are generated by fixture code after clicking the run button.
They measure component processing and rendering, not native input latency.
The harness runs development source with React profiling overhead and without
CPU throttling. Browsers that cannot paint SVG backdrops (Safari) report the
CSS fallback; such a run says nothing about SVG refraction cost. Hardware,
browser, DPR, reduced-motion mode, run label and time are included in the
report. A benchmark is evidence for optimization, not a performance guarantee.

## SVG audit

Open `http://127.0.0.1:3011/?audit=1` to see the documentation comparison and
inspect the native SVG filter definition. DOM metadata cannot read composed
backdrop pixels, so visual acceptance still needs browser screenshots.

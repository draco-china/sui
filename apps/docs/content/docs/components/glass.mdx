## Usage [#usage]

```tsx
import { GlassSurface } from "@workspace/ui/components/glass";

<GlassSurface className="rounded-2xl bg-background p-6">
  Glass surface
</GlassSurface>
```

Use the component's `glassConfig` to choose its material and rendering mode; `glass` remains a boolean switch. Local configuration retains the four options `strength`, `tint`, `tintOpacity`, and `highlight`. Blur and minimum text contrast remain internal. Configuration never becomes an HTML attribute, and explicit `glass={false}` always disables the effect.

```tsx
import { Button } from "@workspace/ui/components/button";
import { GlassSurface } from "@workspace/ui/components/glass";

<GlassSurface glassConfig={{ mode: "svg", material: "clear" }} />
<Button glass glassConfig={{ material: "regular" }}>Action</Button>
```

Each enabled surface uses an independent request. Internal observers, event listeners, renderers and capability probes are shared. Compound roots pass settings to their controls and popups without acquiring a renderer themselves; no public Provider is required.

## How the surface is rendered [#rendering]

The initial surface uses CSS backdrop blur and an inset highlight following its native radius. Measured SVG highlights replace the initial glow. Native SVG filters the live browser backdrop; only WebGPU replaces the background with a decoded sampled frame. The library defaults to SVG → CSS; only Clear with explicit `mode="auto"` requests WebGPU. Regular uses SVG → CSS even in automatic mode. SVG refraction uses native `feDisplacementMap`; Gaussian blur and a sharper displaced edge are composed by SVG filter primitives. Both renderers retain the size-aware smooth refraction band. WebGPU background sampling uses up to 2x resolution, capped at 8 megapixels, with CSS coordinates preserved. SVG generates only a geometric displacement map and does not capture the background.

Glass keeps its boolean switch; `glassConfig.material` selects `"clear"` or `"regular"`. Clear is the default, with `10%` tint opacity; Regular uses `35%`. Select Regular with `<GlassSurface glassConfig={{ material: "regular" }} />`. Explicit `options.tintOpacity` overrides either material's default. The Playground follows the selected default until you adjust transparency; Reset defaults restores the selected material's value.

Skeleton fixes its glass material to Regular with CSS internally and never requests an enhanced renderer. Its public API remains the boolean `glass` switch. Components that need refraction follow their local or inherited configuration; fixed material policies are reserved for components with that requirement.

The two material names follow [Apple's Clear and Regular variants](https://developer.apple.com/design/human-interface-guidelines/materials). Their numeric settings here are Web approximations, not Apple specifications. Both retain refraction strength `22` and highlight `0.3`. Blur remains built in: WebGPU `2px`, SVG `4px`, CSS `6px`.

Surfaces compose background refraction, glass tint, component paint, edge highlights, and content in that order. `tintOpacity` controls the glass tint independently of component paint and highlights. Opaque primary paint remains solid, and translucent destructive paint retains its own alpha. Highlights sit above the paint. CSS, SVG, and WebGPU use the same composed material.

Fully opaque paint uses CSS with the shared SVG highlight, avoiding background capture and refraction that the paint would cover. Translucent surfaces use the selected enhancement mode. Rendering status reports the mode actually used.

## Inputs, viewers, overlays [#composition]

Enable material-bearing surfaces and operation controls with `glass`. Containers such as Card, Accordion and Toolbar use one continuous surface; their rows, labels and dividers do not acquire separate material. Controls inside a glass surface reuse that surface unless explicitly enabled. Floating menus and tooltips can have their own surface. `glass={false}` disables the component and its inherited setting; descendants can explicitly opt back in. Glass focus adds no ring. Ordinary components retain their native theme and focus styling.

Labels, breadcrumbs, layout helpers, status indicators, tables, and QR codes keep ordinary styles. Markdown and HTML viewers stay plain. Editors, code and diff viewers, image viewers, carousels, and attachments apply Glass only to operation controls. Their content remains ordinary, and the editor retains its existing Monaco lifecycle. Small state controls and skeletons use Regular with CSS internally. The Playground shows these ordinary components alongside eligible surfaces without adding a glass card around every example.

## WebGPU sampling and live SVG [#webgpu]

For WebGPU, use `glassConfig.captureTarget` to limit the sampling area. Matching targets, scene revisions, and occlusion sets share snapshots. Capture excludes the surface itself, Glass peers on the same paint level, and higher occluders, while retaining lower painted layers. Levels follow the owning Glass surface and CSS stacking context; the live DOM is never hidden or removed. Changes to a retained lower Glass layer refresh its upper consumers. If a lower native backdrop filter cannot be preserved by DOM capture, the upper surface locally falls back to SVG, then CSS; independent requests can still use WebGPU.

Each request filters ordinary nodes against its optical footprint, with padding for refraction and blur. Shadows, filters and visible pseudo-elements can paint beyond element rectangles, so they are conservatively retained. Excluded images become layout placeholders in the detached clone before resource embedding. Excluded canvases are skipped before pixel serialization, then replaced with equally sized layout placeholders in the clone. A retained resource that cannot be read or embedded falls back locally to SVG, then CSS; independent requests retain WebGPU. Unsupported resources share the existing snapshot failure entry until scene invalidation or refresh; transient capture failures keep the previous frame and remain retryable.

Automatic surfaces use native SVG during scrolling or marked motion when it is available, then retry WebGPU after movement stops. A playing video mixed with other retained DOM paint also stays native; pausing retries WebGPU, while media-only video textures remain eligible for GPU rendering. This keeps live backgrounds from depending on repeatedly discarded DOM snapshots.

DOM capture is capped at `5Hz`, or `10Hz` during movement when native SVG is unavailable; this is not live `60/120Hz` rendering. `refreshGlass(target)` requests new frames for mounted surfaces using the target; omit the target to refresh all mounted requests. The Playground retains both video backgrounds. Native SVG and CSS follow browser playback and scrolling without JS background snapshots; their actual frame rate depends on browser paint and the display.

## Themes and fallback [#themes]

Default theme tokens remain unchanged, and tint comes from the component background. Minimum text contrast remains internal at `0`, with no public option. Component text colors stay unchanged. Rendering failures fall back through the selected backend chain. Reduced-transparency and forced-color preferences disable enhancement, show an opaque base, and retain native focus styles. Check text readability against the actual scene in CSS and SVG fallback.

## Snapshot limitations [#limits]

These limitations apply to WebGPU background capture. Native SVG uses the browser backdrop and does not enter this DOM capture path. DOM capture is not a browser compositor screenshot. Cross-origin images need CORS; iframes, complex transforms, and browser-managed content may not sample accurately. If excluding a canvas cannot reliably preserve a Shadow DOM slot layout, that surface uses native SVG, then CSS. Large capture areas, fast animations, and many overlays increase cost. WebGPU retains the existing snapshot structure without additional live canvases, nested composition layers, or global theme backups.

## API reference [#api-reference]

| Prop | Type | Default / behavior |
| --- | --- | --- |
| Config `mode` | `"css" \| "svg" \| "auto"` | `"svg"`; SVG → CSS. Clear `auto`: WebGPU → SVG → CSS; Regular: SVG → CSS. |
| Config `material` | `"clear" \| "regular"` | `"clear"`; tint opacity `10%` / `35%`. |
| Config `options` | `GlassOptions` | Local material settings. |
| Config `captureTarget` | `HTMLElement \| null \| RefObject<HTMLElement \| null>` | Optional WebGPU capture area. SVG and CSS do not use it. |
| `refreshGlass(target?)` | `(target?: GlassCaptureTarget) => void` | Refresh mounted requests for the target, or all requests when omitted. |
| Options `strength` | `number` | `22` |
| Options `tint` | `string` | Component background. |
| Options `tintOpacity` | `number` | Material default: `0.1` / `0.35`; explicit values override. |
| Options `highlight` | `number` | `0.3` |
| Surface `glass` | `boolean` | `true` |
| Component `glassConfig` | `GlassConfig` | Local `mode`, `material`, `options`, and optional WebGPU `captureTarget`; no enable flag or request ID. |
| Surface other props | Native div props | `className`, `style`, `ref` |
